# 受信代理、备份与恢复工具

本模块完成当前单 API + SQLite 生产准备中的代理限额身份和数据恢复工具，不代表已部署生产 HTTPS 或已通过真实 GPU 故障恢复。

## 受信代理配置

默认不信任任何转发头，认证与公开邮件接口按 TCP 对端 IP 限额。反向代理上线后，在 API 环境变量配置真正连接 API 的代理地址：

```dotenv
TRUSTED_PROXY_IPS=127.0.0.1,::1
PUBLIC_ORIGIN=https://实际控制台域名
```

只在反向代理确实从这些地址连接时使用该例。不要把客户端网段、公共 Wi-Fi 出口、共享代理或不受控主机加入列表。当前支持最多 32 个精确 IPv4/IPv6 地址，拒绝 CIDR、域名、端口、方括号和 zone ID；不预设“内网地址都可信”。配置错误拒绝启动。

- 直接 TCP 对端不可信时忽略 X-Forwarded-For、X-Real-IP 和 Forwarded。
- 对端可信时，从 X-Forwarded-For 右侧向左，只穿越已配置的可信节点，使用第一个不可信地址；客户端伪造的左侧前缀不能替换真实来源。
- 最多 8 跳、1024 字符；缺失、非 IP、重复形式不明确或超限时退回 TCP 对端。代理必须清洗请求头；异常头回退可能让异常请求共享代理限额，不能承诺这些请求仍能按用户分离。
- IPv6 压缩/大小写及 IPv4-mapped IPv6 规范化，避免同一来源通过不同写法绕过限额。
- 仅更新登录/注册的 IP 限额和公开邮件 IP 限额；已有用户、邮箱哈希、支付、模型请求和余额规则不变。不根据转发 Host/Proto 更改同源规则、Cookie 或邮件链接来源。

单层受控代理应覆盖外部 X-Forwarded-For，填入它实际看到的客户端地址；多层代理必须逐层清洗/正确追加，并只信任受控中间跳。不能直接使用客户端最左边的 IP。默认 API 仍监听 127.0.0.1，不因本配置对公网开放。

反向代理仍须按已有部署契约提供 HTTPS、静态 dist、/api 与 /v1 转发，并为 SSE 关闭缓冲。生产 PUBLIC_ORIGIN 与 SMTP/Stripe 固定来源配置见相应文档。此模块没有安装系统代理、申请证书或修改用户机器的网络服务。

## 一致性备份

使用 Node 内置 sqlite.backup，以只读连接取得包含已提交 WAL 的一致性快照；不复制正在运行的主 sqlite 文件。该接口在 Node 22.16 已提供，符合本项目 Node 22.18+ 基线。参见 [Node SQLite backup](https://r2.nodejs.org/download/release/v22.23.0/docs/api/sqlite.html) 与 [SQLite 在线备份说明](https://www.sqlite.org/backup.html)。

```sh
npm run db:backup -- data/backups/pre-release.sqlite
npm run db:verify -- data/backups/pre-release.sqlite
```

源为 .env / 进程环境中的 DATABASE_PATH，默认 data/corematrix.sqlite。每次选择一个新文件名；命令拒绝覆盖已有目标、符号链接和遗留 -wal/-shm/-journal，包括误把源文件作为目标。

在目标所在目录创建私有临时目录（0700），完成 SQLite 快照、结构/外键检查和只读业务对账后，文件设为 0600，以不能覆盖已有目标的原子硬链接发布。两个进程争抢同一目标只能有一个成功；失败清理临时目录。需要支持硬链接的本地文件系统；不支持时明确失败，不降级为可覆盖复制。

备份保留账户、密码哈希、会话/Key、账本、请求结果、GPU 占用、租用/预约、支付、成本与告警。目录权限不是加密或异地备份；生产须在受控存储中管理保留期、磁盘余量、加密和异地副本。命令不自动上传、归档或删除历史备份。

备份可能因持续写入而重新复制，并产生磁盘 I/O，不承诺对生产负载零影响。未完成时不发布目标；突然终止可能留下私有 .corematrix-backup-* 目录，确认没有备份进程使用后才能删除。源数据库保持原样。

## 只读核验

```sh
npm run db:verify -- data/corematrix.sqlite
```

检查在一个只读事务快照中完成：

- SQLite quick_check 和 foreign_key_check；识别 CoreMatrix 核心表和 schema 版本。
- 用户、模型、账本、请求、部署、订单、支付和告警的记录数；pending 请求数与未释放 GPU 占用数。
- 当前 schema 复用 reconciliation 的资金/冻结、Token/GPU/支付账本、预约和资源检查。仅输出 healthy 与按诊断码聚合的数量，不打印账户邮箱、密码哈希、密钥、prompt、实体 ID 或金额。

不会迁移 schema、清理过期会话/限额、恢复 pending 请求、偿还欠款、改余额或释放 GPU。旧版 schema 报 needsMigration=true、reconciliation=null，必须在隔离副本升级后再核验；比当前程序更新的 schema 拒绝操作。结构或外键检查失败不会发布新备份/恢复文件。

合法结构中的资金差异、已记录欠款或支付审查仍保留并备份，禁止自动修复来使结果“正常”。verify 返回退出码 2 提醒人工处理；不把已记录欠款等同于数据库文件损坏。备份/恢复结构成功时返回 0，但必须检查 reconciliation 字段后再决定是否上线。用管理端只读对账定位具体记录。

输出 SHA-256 用于已关闭、无 WAL 的备份文件传输核验；检查存在 WAL 的实时库时 sha256 为 null。不要用实时主文件的哈希替代包含 WAL 的快照，也不要根据哈希推断真实支付到账或 GPU 清理状态。退出码 1 表示操作/结构失败；原始 SQL/凭据不打印，错误采用固定诊断码。

## 恢复到新路径

```sh
npm run db:restore -- data/backups/pre-release.sqlite data/recovery-check/corematrix.sqlite
npm run db:verify -- data/recovery-check/corematrix.sqlite
```

恢复同样使用 SQLite 快照，目标必须不存在。不会覆盖当前 data/corematrix.sqlite，不自动更换 DATABASE_PATH，也不启动第二个 API。读取旧备份不会自动重置用户密码、提升权限或补齐余额。

完整恢复顺序：

1. 选定受控备份，验证结构、版本和对账摘要，保留当前数据库的一致性备份。
2. 在新路径恢复并核验。需要升级旧 schema 时，只升级恢复副本，不修改备份原件。
3. 在测试环境验证登录、账单和请求恢复。不要直接带生产 .env 启动第二个副本：它可能探测真实节点、处理期限或发出队列邮件。
4. 切换生产前停止旧写实例，等待在途请求/邮件排空；保持单 API 写入，并明确对外入口和节点控制面的唯一地址。
5. 指向已核验的新 DATABASE_PATH 后启动，观察 pending 请求按既有规则中断解冻。付费订单、预约冻结和物理 GPU 占用必须保留，不能根据备份时间或节点离线直接释放。
6. 向 Agent 获取新鲜容器清单并完成代数/任务对账，核对可能晚于数据库备份的真实容器、Stripe 事件与资金变更，再恢复新销售/部署。不能单靠 SQLite 核验认定物理资源或外部渠道一致。

备份只包含数据库，不包含 .env、模型文件、Jupyter 工作目录、节点配置和 Agent 本机期限文件。生产需另行安全保管相应密钥和数据；尤其 Jupyter 主密钥需要与节点一致，Agent 的本地到期保护文件不能清空后继续运行旧容器。不要把这些秘密复制到聊天或版本控制。

## 当前验证证据

- 7 项代理专项：未授权转发头、受信链/伪造前缀、IPv6/mapped 规范化、非法配置/超限回退、登录 IP 限额、公开邮件限额和同源策略。
- 6 项备份恢复专项：活跃 WAL、账号/冻结/物理占用保留、恢复副本登录与 pending 中断解冻、不覆盖/链接/遗留日志/并发发布、损坏/FK/未来版本拒绝、只读债务/旧 schema 检查、并发资金写入一致性及 CLI。
- 全套 127 项 Node 测试及 TypeScript/生产构建通过；没有数据库版本升级或 Go 协议变化。
- 本机当前数据库已实际在线备份到私有 data/backups，新路径恢复副本通过结构、外键与只读资金检查；全部表的逻辑数据指纹相同，原账户/密码哈希/余额/账本不变。真实副本未启动 API，临时恢复文件已清理。
- 上述本地演练不替代生产存储故障、TLS、外部渠道或 H01–H07 真机验收，仍未完成这些验证。
