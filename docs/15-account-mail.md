# 账号邮件（C01，SMTP 已实现）

当前支持邮箱验证、密码找回、一次性链接确认，以及中英日韩邮件和页面。原注册登录规则保持兼容：未验证账号仍可登录，邮箱验证不会升级角色、增加余额或自动登录其他账号。注册完成后，在账户安全区主动发送验证邮件；尚未设置邮件服务时明确提示未配置并禁用入口。

## SMTP 配置

使用 Nodemailer SMTP 适配；所有配置仅在 API 服务器环境中读取：

| 变量                     | 规则                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| SMTP_HOST                | 留空时禁用邮件功能，不尝试连接默认邮件服务器                                                                      |
| SMTP_PORT                | 1–65535，默认 465                                                                                                 |
| SMTP_SECURE              | true/false；省略时 465 使用直接 TLS，其他端口使用 STARTTLS                                                        |
| SMTP_USER、SMTP_PASSWORD | 开启后必填，不返回前端、不写日志                                                                                  |
| SMTP_FROM                | 纯邮箱地址，须使用邮件服务允许的发件人                                                                            |
| PUBLIC_ORIGIN            | 开启后必填固定站点 origin，无路径、查询、片段和内嵌认证；生产必须 HTTPS，开发 HTTP 仅允许 localhost/127.0.0.1/::1 |

端口 465 通常配置 secure=true；端口 587 配置 secure=false，适配强制 requireTLS，不能降级到明文。保持证书验证，不提供跳过 TLS 校验的开关。连接/问候超时 10 秒，socket 超时 15 秒；每个 API 进程最多同时发送 4 封，正常关闭等待在途发信。邮件只使用固定模板的纯文本内容，禁用文件与 URL 内容加载。配置依据：[Nodemailer SMTP](https://nodemailer.com/smtp)。

填写 `.env` 后重启 API；`GET /api/state` 的 mailEnabled 只表示配置已启用，不代表实际送达。验证邮件只有 SMTP 接受收件人后才提示“已提交至邮件服务”；仍需检查服务商退信、垃圾邮件和收件箱。配置错误会在启动时阻止启用，发信错误不暴露账号、密钥或原始 SMTP 异常。

## API

| 方法与路径                     | 权限 / 请求                                                              | 响应                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| POST /api/account/verification | 登录会话 + CSRF；发送到当前账号邮箱，采用其已保存语言，不接受目标邮箱    | 200 {ok:true}；已验证时不再次发送；未配置或发送失败 503 mail_unavailable               |
| POST /api/auth/verify-email    | 公共、一次性 `{token}`，仍检查 Origin；需要用户点击确认，无 GET 消耗凭证 | 200 {ok:true}，写 emailVerifiedAt；无效、过期、已使用或用途错误 400 invalid_mail_token |
| POST /api/auth/forgot-password | 公共 `{email,locale?}`，语言白名单，默认 zh-CN                           | 无论账号是否存在均 200 {ok:true}，不回传 token 或账号状态；未配置服务则统一 503        |
| POST /api/auth/reset-password  | 公共 `{token,password}`，密码 12–128 字符；仍检查 Origin                 | 200 {ok:true}；凭证无效 400 invalid_mail_token，密码非法 400 invalid_password          |

找回接口先返回统一提示，已知账号的邮件在后台执行；SMTP 失败仍保持相同公开响应，只记录固定不含地址的失败日志。并发超限同样不泄漏账号存在与否。该流程当前没有自动重发队列，未收到邮件可重新申请，失败不能宣称已经送达。

公共邮件操作按远端地址限 30 次/15 分钟，找回按规范化邮箱哈希限 3 次/小时；验证发送按账号限 1 次/分钟及 10 次/小时。API 仍监听 loopback；已实现 TRUSTED_PROXY_IPS 精确受信代理与链解析，默认忽略转发头。生产按真实代理拓扑配置并清洗来源，详见 [代理契约](19-proxy-backup-recovery.md)。

## 凭证、状态与兼容

schema v7 只新增 users.emailVerifiedAt（旧账号为 null）和 account_tokens：tokenHash 主键、userId、purpose（verify/reset）、expires、createdAt，UNIQUE(userId,purpose)。不修改原账号密码、角色、余额、历史消费和订单；不把旧用户自动标为已验证。

凭证使用 32 字节随机数，数据库只保存 SHA-256 哈希。验证 24 小时有效，重置 30 分钟有效；新申请替换同账号同用途的旧凭证。两种用途互不替代，超时与消费必须在数据库事务内再次检查。发信失败删除本次凭证，保留其他请求产生的更新凭证；SMTP 是否已经接受的网络歧义可能导致用户需要重新申请。

重置新密码哈希在事务外计算，随后事务内重验凭证、更新密码、删除本人全部会话/API Key/邮件凭证。并发消费只有一次成功；无效密码不消耗有效凭证。其他用户不受影响。旧密码登录的异步验证完成后还会核对当前密码哈希，避免重置竞争时重新发出旧凭证会话。运行中的已授权计算仍按原订单和请求计费，不因密码重置自动停止或免单。

链接采用固定 PUBLIC_ORIGIN：`/#/user/account?mail=verify|reset&token=...`。凭证位于 fragment，不进入服务器 GET 查询或 Referer。页面仅保存在内存，并用 history.replaceState 移除地址栏凭证，不写入 localStorage/sessionStorage。需明确点击验证或提交新密码；页面重载后须重新打开原邮件链接。四语言切换保留表单草稿，重置页要求两次密码一致；登录态撤销后仍保留完成提示。

成功响应丢失时，已消费凭证不会再生效：验证可在账户页查看 emailVerifiedAt；重置可尝试用刚设置的新密码登录，必要时重新申请链接。邮件服务的真实投递、TLS 证书与发件人授权仍需维护者环境验收。
