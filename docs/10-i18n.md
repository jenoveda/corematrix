# CoreMatrix 国际化设计

用户已确认首期支持 **简体中文、英文、日文和韩文**。四语言已接入现有页面、弹窗、状态与错误映射；后端 message 保留供调试使用。资源键一致性已自动验证，正式对外发布前仍需母语审校。

## 支持语言

| 标准 locale | 语言菜单显示 | 资源文件                    |
| ----------- | ------------ | --------------------------- |
| zh-CN       | 简体中文     | `src/i18n/locales/zh-CN.ts` |
| en-US       | English      | `src/i18n/locales/en-US.ts` |
| ja-JP       | 日本語       | `src/i18n/locales/ja-JP.ts` |
| ko-KR       | 한국어       | `src/i18n/locales/ko-KR.ts` |

默认 locale 为 zh-CN。浏览器的 en、ja、ko 分别映射到上述规范值；不把 zh-TW 自动宣称为已有繁体翻译，可以回退中文并保持菜单明确为简体中文。

## 范围

必须翻译标题、导航、按钮、表单标签、校验、登录、权限、空状态、表格列名、状态标签、成功通知、确认弹窗、复制反馈、加载提示、计费说明及 aria-label。

以下数据保留原值：模型 ID、GPU UUID、服务器名、用户姓名、模型自定义名称、用户备注、人工入账说明、上游模型输出、技术日志和事件原始摘要。状态码、错误码、JSON 字段与任务协议不翻译。

模型 tag 等当前自由文本属于管理员配置；若要翻译固定分类，应另建分类代码，不通过比较“深度推理”这样的中文字符串确定分类行为。

## 偏好与持久化

登录用户以服务端 user.locale 为准。访客按本机明确选择、浏览器语言、zh-CN 的顺序解析。

选择语言后立即更新 UI；访客只写 `corematrix.locale`，登录用户同时调用 `PUT /api/account/preferences` 保存。不得为语言功能恢复旧的整个 State 本地缓存。

保存失败仍保留本次本机语言，并显示本地化提示“本次已切换，账号偏好保存失败”；下次登录按服务端有效偏好解析。退出登录保留当前浏览器语言，不改变模型、账户余额或路由。

切换语言不重载页面，不丢失未提交表单、不重新发送模型请求，也不再次生成幂等键。多个浏览器标签页可通过 storage 事件同步访客偏好；不通过该事件同步资金状态。

## 实现边界

首版用 React context、类型化字典和浏览器 Intl 即可，不为四种静态语言引入服务端翻译服务。若后续需要复杂 ICU 复数、远程翻译管理和运行时语言包，再引入成熟国际化库。

以 zh-CN 的语义键作为类型基准，其余语言实现完整同构键集合。建议提供 `t(key, params)`、当前 locale 和 `setLocale`，组件不自行维护语言状态。

命名示例：`nav.servers`、`auth.login.submit`、`deployment.phase.ready`、`errors.gpu_unavailable`、`billing.inputPrice`。不要使用中文整句作为 key，也不要通过字符串拼接形成语法句子。

## 服务端错误

已实现的错误格式在原有结构上增量扩展：

```json
{
  "error": {
    "code": "insufficient_gpu_memory",
    "message": "GPU memory is below the required threshold.",
    "details": { "requiredMiB": 40960, "availableMiB": 32768 }
  },
  "requestId": "request-uuid"
}
```

UI 用 code 选取本地化文案，以 details 插值；message 留作接口调试。已提供 invalid_email、invalid_password、unsupported_locale 以及 invalid_text/invalid_integer/invalid_option/invalid_boolean/invalid_object 等稳定代码。校验 helper 使用规范字段路径；前端不解析中文 message。

未知 code 显示当前语言通用失败提示及 requestId，不默认把任意上游原文当成用户可读翻译。技术详情可在管理员事件详情中保留原文。

原生 HTML validationMessage 随浏览器语言变化，不能保证随应用选择改变。必填、格式、长度、范围的业务校验提示要通过本产品翻译资源生成；保留原生控件、label 和有效性状态。

## 金额 日期和数字

使用 `Intl.NumberFormat(locale, {style:'currency',currency:'CNY',minimumFractionDigits:2,maximumFractionDigits:6})` 显示金额。语言切换不改变币种，不自动换汇。

时间使用 `Intl.DateTimeFormat`，语言来自当前 locale，timeZone 固定 Asia/Shanghai。界面显示 UTC+8 或对应语言的时区说明；每日预算业务日保持一致，不能因切英文改成美国时区。

GPU 统一传 MiB，界面按同一规则转换 GiB并显示单位；百分比、千分位和小数按 locale 格式化。内部数据、API 参数和 CSV 数字保持规范机器值，不把本地化字符串反向当成金额写入数据库。

## 结构化账单迁移

当前 ledger.quantity 和 resource 存中文或自定义自由文本。新增结构化 metadata，例如 `{inputTokens,outputTokens,modelId,reason}`，新账单用 type + metadata 生成翻译文案。

旧账单没有可恢复数据时保留原文并标注“原始记录”，不通过正则猜测并重写历史账本。金额、时间、状态标签仍可按当前语言展示。

## 验收

1. 四语言 key 集合完整，不能用 zh-CN 占位冒充日语或韩语已翻译。
2. 用户注册、登录、模型体验、钱包、Key、管理员模型编辑、服务器接入、部署和失败清理均完成四语言冒烟测试。
3. 切换语言后路由、表单、当前回复及请求 ID 不变，不额外提交写请求。
4. API 错误码在四语言下显示正确文案，details 插值不丢失。
5. 日文、韩文及长英文在 375px 窄屏不被截断或导致全页横向溢出。
6. 页面 lang 属性随 locale 更新；屏幕阅读器标签同样翻译。
7. 四语言显示同一微元金额、UTC+8 日期和 GPU 容量，不发生换汇或业务日漂移。
8. 中文、日文、韩文用户名可注册和显示；仅对邮箱等机器标识使用相应规范化。

## 错误详情交付记录（2026-10-16）

共享 text/int/object 校验、注册与密码、模型配置、服务器、GPU 购买/预约/续费、成本、充值和预算接口已接入结构化错误。细分推理 URL/允许来源、模型 ID、密钥变量名、受控模型来源/固定版本、节点地址、运行模板上下文/并行数及按卡销售配置。

| details 字段                     | 语义与显示                                                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| field                            | 规范字段路径，如 name、inputPrice、portEnd、runtime.minGpuMemoryMiB；从前端允许表选择翻译标签，不显示任意传入字段名。                    |
| min / max                        | 服务端约束，文本长度或整数范围；inputPrice/outputPrice/amount/hourlyPrice/expectedHourlyPrice/dailyBudget 以整数微元传输、CNY 格式显示。 |
| requiredMiB / availableMiB       | 所选 GPU 的最低单卡显存与模型要求，整数 MiB，不把容量缺口当作实际吞吐测量。                                                              |
| requiredCards / availableCards   | 模型所需卡数与节点当前空闲卡数，不能据此宣称所有空闲卡都匹配类型或预约时段。                                                             |
| requiredAmount / availableAmount | 本次最大冻结额与本人可用余额/剩余日预算，整数微元，仅本人鉴权调用返回。                                                                  |

错误包含与 X-Request-ID 一致的 requestId。真实推理创建请求后使用其持久化 ID，失败重放和恢复保留原 ID；原有 OpenAI 风格 request_id 字段保留兼容。请求校验失败尚未创建推理记录时，ID 仅用于 HTTP 日志关联，不能当作已扣费的订单证明。

ApiError 保留结构化 details 和合法 UUID；四语言 formatter 只接受已知字段、非负安全整数及已知参数组合。未知 code、未知字段、无效/缺失参数显示本地化回退和合法请求 ID，不插入服务端原文、不把恶意字符串用作字段标签，也不输出未替换的占位符。服务端 details 不包含提交的字段值、密码、Cookie、Key、完整环境变量、原始推理错误或 prompt。

损坏或无法解析的响应属于结果未知（客户端 status=0、invalid_response），保持原购买/续费/支付请求的幂等恢复语义，不因响应损坏清除原键或自动新建订单。

原生校验覆盖必填、邮箱/URL、最短/最长长度、上下限、步长、数字和 pattern；切换 locale 后重新生成已有 custom validity 文案，保留字段值，不自动提交业务请求。范围与步长保留微元所需的小数精度，0.000001 不显示为 0。

新增 7 项专项测试，验证四语言字段/金额/资源插值、未知详情、原生约束、客户端 JSON/SSE 错误、HTTP 字段错误、资金/显存缺口及推理重放 ID。全套 114 项 Node 测试与生产构建通过。Chromium 验证错误出现后四语言切换、草稿保留、不额外提交模型写入、真实范围错误、未知错误回退与 375px 布局。无需数据库或 Go 协议迁移；母语审校和真实服务/GPU 验收仍未完成。
