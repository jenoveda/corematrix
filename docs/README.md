# CoreMatrix 开发文档

CoreMatrix 为共享大模型提供按 Token 计费的访问服务，并统一管理自有及供应商 GPU 服务器、模型部署和独享算力订单。这套文档面向产品、前端、后端、节点 Agent 和测试开发，作为后续实现与验收的共同依据。

文档基线日期为 **2026 年 10 月 16 日，UTC+8**。产品界面以已确认的三端入口需求与原型为基础；已实现能力以当前项目源码为准。用户已确认节点环境采用 **Linux、NVIDIA GPU 和 Docker**。

本阶段结果见 [实现与验证记录](11-implementation-status.md)，Go Agent 支持推理与按卡出租（JupyterLab）两种模式；GPU 订单、余额计费、续费退租和到期回收已实现，见 [GPU 购买与计费](12-gpu-rental-billing.md)。节点部署步骤见 [Agent 接入手册](../agent/README.md)。

账号邮件与配置见 [SMTP 验证和密码找回](15-account-mail.md)，在线充值见 [Stripe 支付](16-stripe-payments.md)。

GPU 未来预约、资源计划与延迟计费见 [预约契约](17-gpu-reservations.md)。定期监控、告警和 SMTP 摘要见 [运维告警](18-operations-alerts.md)，受信代理与恢复命令见 [运维工具](19-proxy-backup-recovery.md)，API/节点模板与负载路由见 [生产部署](20-production-deployment.md)。

完整的新增业务契约：[GPU 购买与计费](12-gpu-rental-billing.md)、[流式推理与计费](14-streaming-billing.md)。

Linux 一键启动前后端与独立测试数据卷见 [Docker Compose 测试部署](21-compose-testing.md)。

三端独立入口与管理后台上传 HTTPS 证书见 [身份隔离与证书](22-portals-certificates.md)；第三方供应商接入、两种销售方式、固定采购卡时与结算见 [供应商采购](23-suppliers-procurement.md)。这两章替代旧文档中同入口登录和供应商未实现的描述。

## 状态约定

- **已实现**：当前源码已经提供该能力；不等于已在真实 GPU 上验收。
- **待开发设计**：后续实现应遵循的目标契约；当前接口可能返回 404。
- **后续阶段**：原型需要，但不包含在下一阶段服务器管理和部署交付中。

## 全局约定

| 项目         | 约定                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 产品语言     | zh-CN、en-US、ja-JP、ko-KR；默认简体中文                                      |
| 货币与精度   | CNY，整数微元；1 元等于 1,000,000 微元                                        |
| 日期         | API 显示 UTC ISO 8601；节点任务内部用 epoch 毫秒，业务日按 Asia/Shanghai 归集 |
| 用户访问模型 | 始终使用平台模型 ID，不直接访问节点容器                                       |
| GPU 身份     | 以设备 UUID 为准，index 只用于展示                                            |
| 权限         | 用户、管理员、节点 Agent 的凭证和作用域分离                                   |
| 资源安全     | 节点离线、任务超时不等于 GPU 可以重新分配                                     |
| 技术范围     | 当前保留 React、Node.js 和 SQLite；不预先引入 Kubernetes、Redis 或消息中间件  |
