## 成本和对账契约（v6）

- `POST /api/admin/costs`：管理员及 CSRF，body 为 category/day/amount/reason/reference/serverId（可空）。CNY 整数微元，金额 1–100,000,000,000,000 微元，日期为有效 YYYY-MM-DD。category 为 equipment/electricity/bandwidth/storage/operations/upstream/other；设备、闲置和异常成本按实际单据归入对应分类。
- reference 为唯一单据编号（8–100 位字母、数字、._-）。相同编号同内容重试返回原记录，不重复累计；冲突 409。保留操作者、创建时间与关联服务器名称快照。
- `POST /api/admin/costs/:id/void`：管理员及 CSRF，body `{reason}`。保留原金额和单据，补充作废原因/操作者/时间；相同原因重复提交幂等，修改原因 409。更正通过作废后新增单据完成，不能删除审计链。
- `GET /api/admin/reports?from=YYYY-MM-DD&to=YYYY-MM-DD&before=<cursor>`：管理员，最多查询 366 日。相同 UTC+8 期间汇总 Token/GPU 净消费、充值、有效成本、分类、模型、每日数据。充值不算收入，退款为负消费；成本不修改用户余额。单据每页 50 条，nextCursor 为 null 表示结束，聚合不受分页影响。
- profit 为净消费收入减已录入成本。无有效成本单据时返回 null；存在单据时也仅标为按已录入成本计算，不能宣称完整审计毛利或暗示不存在未录入成本。
- `GET /api/admin/reconciliation`：管理员，只读 `{checkedAt,healthy,issues}`；检查余额、冻结、Token 对应账本、GPU 扣款和退款各自总额、孤立消费账单及停止部署仍占用 GPU。发现异常不修改资金或释放资源；它不代替硬件清单对账或审计。

维护者已确认 Stripe + SMTP，SMTP 与 Stripe 适配已实现，真实投递和商户收款仍待验收。目前没有可用 GPU 测试节点，H01–H07 保持未验收；继续完成不依赖硬件的模块。未发送真实邮件或操作外部 GPU 节点。
